## 1. इस संस्करण में क्या बदला?

V2.3 का लक्ष्य संख्या के लिए जबरन अक्षर-जोड़ बनाना नहीं, बल्कि लिखावट से नियमपूर्वक निकला वास्तविक शब्द चुनना है जिसका अर्थ स्पष्ट हो और जिसे याद रखना आसान हो।

खेल = 11, केक = 111 और गेहूँ = 110 को regression tests बनाया गया है।

य, व, ह, ल के consonant-base से अंक नहीं निकलते; उन पर लगी मात्रा का अंक फिर भी निकलता है।

स्वतंत्र स्वर और मात्रा को समान अंकीय मान दिया गया है; अ का कोई अंक नहीं।

अनुस्वार (ं) = 5, चंद्रबिंदु (ँ) = कोई अंक नहीं, विसर्ग (ः) = 6। यह प्रणाली-विशेष policy है, सार्वभौमिक हिंदी नियम नहीं।

हर उम्मीदवार शब्द का code स्थिर mapping से दोबारा निकाला गया। गलत code या छोड़ा हुआ अंक स्वीकार नहीं किया जाता।

दुर्लभ, क्षेत्रीय, संस्कृतनिष्ठ, उधार और spelling-dependent शब्दों को A-स्तर नहीं दिया गया।

जहाँ सामान्य और अर्थ-स्पष्ट शब्द नहीं मिला, वहाँ “—” रखा गया है। खाली slot, झूठे peg से बेहतर है।

> मुख्य सीमा
> Code-match और शब्द का शब्दकोशीय अस्तित्व दो अलग जाँचें हैं। Encoder यह जाँच सकता है कि “कछ” = 16 निकलता है; वह अपने-आप यह प्रमाणित नहीं करता कि वह आधुनिक सामान्य हिंदी में अच्छा peg है। इसलिए अर्थ, स्रोत, प्रचलन और peg quality अलग दर्ज हैं।

## 5. Encoder के स्थिर नियम

क्रमशः पढ़ें — शब्द के सभी लिखित घटक क्रम में पढ़े जाते हैं। हर mapped consonant और vowel sign के अंक जुड़ते हैं।

अंतर्निहित अ नहीं गिनें — क, ग, न आदि के बाद लिखी मात्रा न हो तो default अ के लिए अलग अंक नहीं निकलता।

स्वतंत्र स्वर = समान मात्रा — उ और ु = 0; ई और ी = 3; ओ और ो = 2 आदि। स्वतंत्र अ = ∅।

वाहक का मूल छोड़ें — य, व, ह, ल अपना consonant अंक नहीं जोड़ते; उन पर लगी मात्रा फिर भी गिनी जाती है।

अनुस्वार बनाम चंद्रबिंदु — ं = 5; ँ = ∅। इसलिए spelling बदलने पर code बदल सकता है। चुनी spelling स्थिर रखें।

विसर्ग — ः = 6; यह नियम अपने-आप संस्कृतनिष्ठ रूप को अच्छा modern Hindi peg नहीं बनाता।

हलंत/संयुक्ताक्षर — हलंत का अंक नहीं; उपस्थित हर वास्तविक consonant अपने नियम से गिना जाता है। र को एक बार ही गिनें।

नुक्ता — नुक्ता चिह्न अलग अंक नहीं। समर्थित nukta letters के लिए explicit mapping है; अज्ञात रूप validation fail करेगा।

Code की लंबाई — निकले हुए अंकों की संख्या वास्तविक code length है। 3-अंकीय output को 2-अंकीय slot में नहीं रखा जा सकता।

शुरुआती शून्य — 04 को string “04” ही रखें; integer 4 में बदलने से peg key बदल जाएगी।

Unsupported notation — ऑ/ॉ, ऍ/ॅ, unlisted consonants या अज्ञात चिह्न मिलने पर candidate को चुपचाप ignore न करें; review के लिए रोकें।

## 15. Peg स्वीकार करने का गुणवत्ता प्रोटोकॉल

पहले सामान्य हिंदी शब्द, फिर प्रचलित उधार शब्द, फिर साहित्यिक/क्षेत्रीय शब्द खोजें; हर स्तर का label रखें।

Exact spelling, अर्थ, स्रोत और क्षेत्र/काल (यदि ज्ञात हो) दर्ज करें।

Encoder का output पहले निकले; human reviewer बाद में शब्द की गुणवत्ता देखे।

केवल वांछित code पाने के लिए गलत spelling न लिखें।

एक code पर कई विकल्प हों तो सबसे आम, दृश्यात्मक और सांस्कृतिक रूप से सुरक्षित शब्द चुनें।

हर release में mapping version store करें; mapping बदले तो सारे पेग और लंबी-संख्या उदाहरण फिर audit करें।

Final approval से पहले दो reviewers 00–99 पर स्वतंत्र coding करें; disagreement को unresolved रखें।

## 17. निष्कर्ष और V2.4 के प्रवेश-द्वार

V2.3 mapping, diacritic policy और code audit को अधिक सुसंगत बनाता है। इससे वे गलतियाँ रुकती हैं जहाँ शब्द का अंतिम consonant या मात्रा छोड़कर छोटा code लिख दिया जाता था।
